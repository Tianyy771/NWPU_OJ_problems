# I Have a Plan! 题解：从暴力枚举到二维偏序与树状数组
 
> 语言：C++17。
>
> [返回题面](./I_have_a_plan.md) · [仓库原版标准程序](./std.cpp)

## 一、先用人话理解题目

达奇找到了 $n$ 个藏身处。第 $i$ 个地点有两个属性：

- $a_i$：一开始的暴露值；
- $b_i$：每天的搜查力度对它的影响系数。

第 $j$ 天的搜查力度是 $c_j$，因此当天结束时，地点 $i$ 的暴露值会增加 $b_i c_j$。

现在，对**每一个地点 $i$**，我们要数出多少个**其他地点 $k$** 满足：

- 在计划开始之前， $k$ 的暴露值不高于 $i$；
- 在第 1 天、第 2 天……直到第 $m$ 天结束时， $k$ 的暴露值都不高于 $i$。

注意两件事：

1. **可以相等**，因为要求的是“不高于”，即 $\le$，不是严格小于。
2. **不能选自己**，即 $k\ne i$。但如果两个不同地点的数据完全一样，它们仍然可以互相充当备用地点。

举个小例子：如果 A 始终是 $[10,10,10]$，B 是 $[8,9,11]$，那么 B **不能**作为 A 的备用地点，因为最后 B 的暴露值变成了 11，超过了 A 的 10。只有每一个检查时刻都满足条件才行。

## 二、最直观的暴力做法

我们可以依次枚举：

1. 被考察的地点 $i$；
2. 候选备用地点 $k$，跳过 $k=i$；
3. 从计划开始一直模拟到最后一天，检查 $k$ 是否始终不高于 $i$。

这样时间复杂度是 $O(n^2m)$。

题目给出 $n,m\le 2\times 10^5$，显然无法承受。

**不要急着学数据结构。** 这道题的第一个突破口是：真的需要检查每一天吗？

## 三、最重要的观察：其实只要检查起点和终点

设前 $t$ 天的总搜查力度为

$$
P_t=\sum_{j=1}^{t}c_j,\qquad P_0=0.
$$

那么第 $t$ 天结束后，地点 $i$ 的暴露值就是

$$
E_i(t)=a_i+b_iP_t.
$$

这说明：虽然题面描述了每天的变化，但一个地点在某一时刻的暴露值，**只和此前搜查力度的总和有关**。

再设所有天的搜查力度之和为

$$
S=\sum_{j=1}^{m}c_j.
$$

因为题目保证 $c_j\ge 0$，所以

$$
0=P_0\le P_1\le\cdots\le P_m=S.
$$

我们希望候选地点 $k$ 始终不高于地点 $i$，即

$$
a_k+b_kP_t\le a_i+b_iP_t
$$

对所有 $t=0,1,\ldots,m$ 都成立。

把两边移到一起，定义差值函数：

$$
D(P)=(a_k-a_i)+(b_k-b_i)P.
$$

**关键在于：** $D(P)$ 是一个关于 $P$ 的一次函数。

一次函数的图像是一条直线。在闭区间 $[0,S]$ 上，它的最大值一定出现在某个端点。因此：

- 如果在 $P=0$ 时有 $D(0)\le 0$；
- 并且在 $P=S$ 时有 $D(S)\le 0$；

那么中间的所有 $P_t$ 都必然满足 $D(P_t)\le 0$。

反过来，如果整个过程中始终满足条件，那么起点和终点当然也满足条件。

于是我们得到了**充要条件**：

$$
\boxed{
\begin{aligned}
a_k&\le a_i,\\
a_k+b_kS&\le a_i+b_iS.
\end{aligned}}
$$

这里还有一个边界情况：当 $S=0$ 时，所有 $c_j$ 都是零，暴露值根本不会变化；上面的两个条件会退化为同一个条件，仍然正确。

### 为什么这个结论很值钱？

原问题需要比较 $m+1$ 个时刻；现在只需要比较**最开始和最后结束时**的两个数字！

对于每个地点，我们定义最终暴露值

$$
R_i=a_i+b_iS.
$$

那么地点 $k$ 是地点 $i$ 的合格备用地点，当且仅当

$$
\boxed{a_k\le a_i\quad\text{且}\quad R_k\le R_i\quad\text{且}\quad k\ne i.}
$$

至此，原题中每天的过程就被彻底消掉了。

## 四、变成经典的二维偏序问题

把每一个地点看成平面上的一个点：

$$
\boxed{(a_i,R_i)}
$$

对于点 $i$，我们要统计有多少个其他点 $k$，同时满足

$$
a_k\le a_i,\qquad R_k\le R_i.
$$

从图像上理解，就是统计点 $i$**左下方（包括水平、竖直边界）**有多少个点，然后排除自己。

这种同时比较两个坐标大小的问题，就是典型的**二维偏序计数**。

此时即使仍然暴力枚举所有点对，复杂度也已经从 $O(n^2m)$ 降到了 $O(n^2)$。但是 $n=2\times10^5$ 时，仍然需要约 $4\times10^{10}$ 次比较，还是太慢。

怎么继续优化？

## 五、先排序，把二维条件变成一维条件

我们现在有两个限制：

1. $a_k\le a_i$；
2. $R_k\le R_i$。

一个很常见的技巧是：

**先按照第一个维度排序，让它自动得到满足；再用数据结构处理第二个维度。**

具体来说：

1. 将所有地点按照初始暴露值 $a_i$ 从小到大排序。
2. 按顺序处理地点 $i$ 时，把初始暴露值不大于 $a_i$ 的地点加入一个数据结构。
3. 在这些已经加入的地点中，查询最终暴露值 $R_k\le R_i$ 的有多少个。

因为已经按 $a$ 排序，所以数据结构里面的地点自动满足第一个不等式。我们只需要快速维护和查询第二个不等式。

这种按照某一维排序、依次向前处理的思路，通常称为**扫描线**。这里的“扫描线”不一定真的画出一条线，可以把它理解成“按照某个顺序逐步加入元素”。

### 一个容易踩的大坑：相同的 $a_i$ 必须成组处理！

假设有两个不同地点：

$$
(a_1,R_1)=(5,10),\qquad (a_2,R_2)=(5,8).
$$

对于第一个地点，第二个地点应该计入答案，因为

$$
5\le5,\qquad8\le10.
$$

可如果排序后，我们遇到第一个地点就立刻查询，第二个地点还没插入数据结构，答案就会被漏算！

原因是：**同一个 $a$ 的地点互相之间也可能满足条件**，而它们在排序后谁先谁后并没有特殊意义。

所以必须按相同的 $a$ 分组：

1. 找到所有 $a$ 相等的地点，记为当前组。
2. **先把整组地点都加入数据结构。**
3. **再逐个查询这一组的答案。**
4. 进入下一组。

这样查询某个地点时，数据结构中恰好包含所有满足 $a_k\le a_i$ 的地点。

另外，自己也已经被加入了，因此每次查询结果最后都要 **减去 1**。

## 六、如何快速统计 $R_k\le R_i$？树状数组登场

现在只剩下一个问题：

> 动态插入一些数 $R_k$，并反复询问“已经插入的数中，有多少个不大于 $R_i$”？

这正是 **树状数组（Fenwick Tree）** 擅长解决的事情。

我们可以维护一个计数数组：每个最终暴露值出现一次，就在它对应的位置增加 1。查询“不大于 $R_i$ 的数量”，实际上就是查询一个**前缀和**。

例如，若已经插入的最终暴露值为

$$
[8,9,12,12]
$$

那么：

- 查询不大于 8 的数量，答案是 1；
- 查询不大于 9 的数量，答案是 2；
- 查询不大于 10 的数量，答案也是 2；
- 查询不大于 12 的数量，答案是 4。

树状数组支持：

| 操作 | 含义 | 时间复杂度 |
| --- | --- | --- |
| 单点加一 | 有一个地点的最终暴露值等于这个位置 | $O(\log n)$ |
| 前缀求和 | 统计最终暴露值不大于某个位置的地点数 | $O(\log n)$ |

### 但是 $R_i$ 可能非常大：需要离散化

因为

$$
R_i=a_i+b_iS,
$$

它可能达到 $10^{18}$ 量级，我们不可能建立这么大的树状数组。

好消息是：我们并不关心具体相差多少，只关心**大小顺序和相等关系**。

因此可以使用**离散化**：

1. 收集所有 $R_i$。
2. 从小到大排序。
3. 用去重操作去掉重复值。
4. 用二分查找找到每个 $R_i$ 的排名，排名从 1 开始。

例如，本题样例的最终暴露值为

$$
[10,12,9,12,8].
$$

排序、去重后得到

$$
[8,9,10,12].
$$

对应排名为：

| 实际最终暴露值 $R$ | 8 | 9 | 10 | 12 |
| --- | ---: | ---: | ---: | ---: |
| 离散化排名 | 1 | 2 | 3 | 4 |

两个 12 都会映射到排名 4，所以相等的情况也能被正确统计。

这里查询的是“**小于等于**”，因此应使用树状数组的前缀和 `query(rank(R_i))`，不能只查到前一个排名。

### 树状数组到底在做什么？

树状数组内部使用

`lowbit(x) = x & (-x)`

决定每个位置负责维护多大的一段区间。

你可以先记住两个接口，不需要在这道题里重新推导整个树状数组：

- `add(p, 1)`：把第 $p$ 个位置的出现次数加一。
- `query(p)`：得到第 1 个位置到第 $p$ 个位置的出现次数之和。

其中两个操作都只需要 $O(\log n)$ 时间。

如果还没有学过树状数组，也可以先把它理解为一个“**支持快速修改单点、快速查询前缀和的计数器**”，然后再回头单独学习它的原理。

## 七、跟着样例手动模拟

题目样例：

~~~text
5 3
10 0
8 2
7 1
10 1
8 0
1 0 1
~~~

总搜查力度是

$$
S=1+0+1=2.
$$

因此，各地点的最终暴露值为：

| 地点编号 | $a_i$ | $b_i$ | $R_i=a_i+b_iS$ |
| --- | ---: | ---: | ---: |
| 1 | 10 | 0 | 10 |
| 2 | 8 | 2 | 12 |
| 3 | 7 | 1 | 9 |
| 4 | 10 | 1 | 12 |
| 5 | 8 | 0 | 8 |

按 $a_i$ 从小到大分组：

**第一组：** $a=7$

只有地点 3，先插入 $R_3=9$。查询 $R\le9$ 的数量为 1，减去自己：

$$
ans_3=1-1=0.
$$

**第二组：** $a=8$

有地点 2 和地点 5。先把它们的 $R=12,8$ **都插入**。此时树状数组中包含 $R=\{9,12,8\}$。

- 地点 2： $R_2=12$，前缀里有 3 个，减去自己， $ans_2=2$。
- 地点 5： $R_5=8$，前缀里有 1 个，减去自己， $ans_5=0$。

**第三组：** $a=10$

有地点 1 和地点 4。先插入 $R=10,12$。此时全部五个地点都已插入，最终暴露值为 $\{9,12,8,10,12\}$。

- 地点 1： $R_1=10$，有 3 个地点满足 $R\le10$，因此 $ans_1=3-1=2$。
- 地点 4： $R_4=12$，全部 5 个地点都满足 $R\le12$，因此 $ans_4=5-1=4$。

最后**按照原始编号**输出：

~~~text

2
0
4
0
~~~

与题目样例一致。

## 八、完整 C++17 代码（带注释）

以下代码保留仓库 [std.cpp](./std.cpp) 的核心思路，整理了变量名与注释，便于第一次学习的同学阅读。

~~~cpp
#include <bits/stdc++.h>
using namespace std;

// 树状数组：维护每个“最终暴露值排名”出现了多少次
struct Fenwick {
    int n;
    vector<int> tree;

    explicit Fenwick(int n) : n(n), tree(n + 1, 0) {}

    // 在位置 pos 上加 value
    void add(int pos, int value = 1) {
        for (; pos <= n; pos += pos & -pos) {
            tree[pos] += value;
        }
    }

    // 查询区间 [1, pos] 的出现次数总和
    int query(int pos) const {
        int result = 0;
        for (; pos > 0; pos -= pos & -pos) {
            result += tree[pos];
        }
        return result;
    }
};

struct Place {
    long long a, b;      // 初始暴露值、敏感程度
    long long finalValue; // 最终暴露值 R = a + b * S
    int rank;             // finalValue 的离散化排名
    int id;               // 原始输入编号
};

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n, m;
    cin >> n >> m;

    vector<Place> places(n);
    for (int i = 0; i < n; ++i) {
        cin >> places[i].a >> places[i].b;
        places[i].id = i;
    }

    // 我们只需要所有天搜查力度的总和 S
    long long S = 0;
    for (int j = 0; j < m; ++j) {
        long long c;
        cin >> c;
        S += c;
    }

    // 计算每个地点的最终暴露值，并收集起来离散化
    vector<long long> values;
    values.reserve(n);
    for (auto &p : places) {
        p.finalValue = p.a + p.b * S;
        values.push_back(p.finalValue);
    }

    // 排序 + 去重
    sort(values.begin(), values.end());
    values.erase(unique(values.begin(), values.end()), values.end());

    // lower_bound 找到第一个 >= finalValue 的位置
    // 因为 finalValue 一定在 values 中，所以得到的就是它的排名
    // 树状数组下标从 1 开始，因此需要 +1
    for (auto &p : places) {
        p.rank = int(lower_bound(values.begin(), values.end(),
                                 p.finalValue) - values.begin()) + 1;
    }

    // 对第一个维度 a 排序
    sort(places.begin(), places.end(),
         [](const Place &x, const Place &y) {
             if (x.a != y.a) return x.a < y.a;
             return x.id < y.id;
         });

    Fenwick bit(n);
    vector<int> ans(n);

    // 按相同的 a 分组处理
    for (int l = 0; l < n; ) {
        int r = l;

        // 当前组为 [l, r)，其中 a 全部相等
        while (r < n && places[r].a == places[l].a) {
            ++r;
        }

        // 先把这一组的所有最终暴露值插入
        for (int i = l; i < r; ++i) {
            bit.add(places[i].rank);
        }

        // 再查询这一组：同时满足 a_k <= a_i、R_k <= R_i
        for (int i = l; i < r; ++i) {
            const Place &p = places[i];

            // 查询结果包含地点自己，所以减去 1
            ans[p.id] = bit.query(p.rank) - 1;
        }

        l = r; // 下一组
    }

    // 必须按照原始输入顺序输出
    for (int x : ans) {
        cout << x << '\n';
    }

    return 0;
}
~~~

### 代码最值得理解的地方

整段代码看起来较长，但真正的算法核心只有三个动作：

1. **预处理**：将每个地点变成 $(a_i,R_i)$。
2. **排序并分组**：让已经插入的地点满足 $a_k\le a_i$。
3. **树状数组前缀查询**：在已插入地点中数出 $R_k\le R_i$ 的个数，再减去自己。

其他代码主要是在实现离散化、保存原始编号和维护树状数组。

## 九、正确性证明

我们把证明拆成两个部分。

**引理 1：地点 $k$ 能作为地点 $i$ 的备用地点，当且仅当 $a_k\le a_i$ 且 $R_k\le R_i$。**

证明：由第三节可知，两个地点暴露值的差 $D(P)$ 是一次函数；所有检查时刻对应的 $P_t$ 均位于 $[0,S]$ 内。一次函数在区间上的最大值位于端点，因此两个端点均不大于零，当且仅当整个计划中的差值始终不大于零。证毕。

**引理 2：算法查询地点 $i$ 时，树状数组恰好包含所有 $a_k\le a_i$ 的地点，每个地点出现一次。**

证明：算法按 $a$ 从小到大处理。比当前 $a_i$ 小的组均已插入；当前 $a_i$ 相等的整组也已在查询前插入；比当前 $a_i$ 大的组尚未插入。因此结论成立。每个地点只在所属组被插入一次。证毕。

**定理：算法输出的每个答案都是正确的。**

证明：根据引理 2，查询时树状数组只包含且包含全部满足 $a_k\le a_i$ 的地点；前缀和查询进一步筛选出满足 $R_k\le R_i$ 的地点。根据引理 1，这恰好是全部合格备用地点再加上地点 $i$ 自己。由于自己必然满足两个非严格不等式，减去 1 就得到题目要求的其他地点数量。证毕。

## 十、复杂度分析

- 读入并求总搜查力度： $O(n+m)$；
- 计算最终暴露值： $O(n)$；
- 离散化中的排序和二分： $O(n\log n)$；
- 按 $a$ 排序： $O(n\log n)$；
- 每个地点恰好插入一次、查询一次，每次 $O(\log n)$：总共 $O(n\log n)$。

因此最终：

$$
\boxed{\text{时间复杂度 }O(m+n\log n)}
$$

$$
\boxed{\text{空间复杂度 }O(n)}
$$

注意这里是边读入边累加 $c_j$，不需要额外保存 $m$ 天的数组，因此空间复杂度不含 $O(m)$。

## 十一、容易出错的细节

1. **不能只比较最后一天。** 初始条件 $a_k\le a_i$ 也必须成立。最后比较通过，不代表最开始也通过。
2. **只比较起点和终点依赖 $c_j\ge0$。** 正因为前缀和 $P_t$ 始终在 $[0,S]$ 内，端点比较才足够。如果搜查力度可以为负数，这一步就需要重新分析。
3. **处理相同的 $a$ 时必须先整组插入，再整组查询。** 否则相同 $a$ 的地点可能被漏掉。
4. **相等是合法的。** $(a_k,R_k)=(a_i,R_i)$ 且 $k\ne i$ 时， $k$ 应当被计入。离散化不能错误地去掉地点本身，只是对坐标值去重。
5. **每次查询都要减去 1。** 因为地点自己已经插入，但题目只允许其他地点。
6. **要保存原始编号。** 排序会改变地点顺序，输出却必须按输入顺序。
7. **最终暴露值要用 long long。** $S$ 最大可达 $2\times10^9$，乘上 $b_i$ 后可能达到 $2\times10^{18}$，远超 32 位整数范围。
8. **树状数组下标从 1 开始。** 使用 lower_bound 得到的是从 0 开始的下标，别忘记加 1。

## 十二、最后再回顾一下这道题的思维链

这道题真正难的，不是把树状数组敲出来，而是发现怎样把题目一步步变成它能解决的形式：

$$
\boxed{
\begin{gathered}
\text{逐天比较暴露值}\\
\Downarrow\\
\text{一次函数：只比较起点和终点}\\
\Downarrow\\
\text{统计 }a_k\le a_i,\ R_k\le R_i\\
\Downarrow\\
\text{二维偏序：先按 }a\text{ 排序}\\
\Downarrow\\
\text{树状数组维护 }R\text{ 的前缀计数}
\end{gathered}}
$$

以后遇到类似题目，可以尝试问自己：
